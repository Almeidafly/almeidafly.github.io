Defense-oriented software engineering

Software for systems that have to keep working.

Almeidafly builds open tooling that makes software supply chains verifiable, CI pipelines honest, and telemetry and autonomous systems easier to trust. Every claim on this page links to public work you can inspect.

Mission

Make mission software provably buildable and tamper-evident, from the dependency tree to the test run, and publish the work in the open so anyone can check it.

Capability areas

Software supply-chain assurance

Dependency risk tracking, controlled delivery of patched dependencies, and detection of default settings that change silently between versions.

CI hardening

Least-privilege GitHub Actions, security scanning, merge-result testing, and detection of faked or weakened tests.

Space and telemetry tooling

Reproducible pipelines for public mission data, thermal modeling, and load-aware compute throttling.

Autonomous systems

Approval-gated robot control loops with allowlists and kill switches, plus mobile sensor logging.

Tooling we maintain

Supply chain and CI

  • patch-cloud: opt-in npm registry that serves a fixed fork while upstream CI is failing
  • lit-dark: reproducible lit/dark CI status standard
  • fakegreen: detects skipped, deleted, or weakened tests in agent-written diffs
  • merge-guard: tests the merged result of every PR and blocks merges that would break CI
  • knobs: tracks default parameters that change silently between versions

Space and telemetry

  • marslog: daily cache and per-sol changelog of public NASA Mars rover data, with a Curiosity air-temperature model
  • heatgate: pauses heavy compute when the machine runs hot
  • Concept in progress: combining the two so rover-class compute can throttle ahead of forecast thermal limits

Autonomous systems

  • x-robot: approval-gated browser robot with a localhost allowlist and a STOP kill switch
  • phone-robot: Android GPS, activity, and motion logging to a self-hosted server
